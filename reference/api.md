# Техсправка: что работает, что нет

Проверено на online-edu.mirea.ru (Moodle 4.5) и pulse.mirea.ru в сентябре 2026.

## Доступ к СДО

Токенов нет и не будет:
- `/user/managetoken.php` — пусто, студентам не выдают право создавать ключи;
- `/login/token.php` — `invalidlogin` даже с верным паролем: аккаунт живёт через Keycloak (`auth=oidc`), локального пароля в Moodle нет.

Остаётся сессия браузера. Вызов идёт через `/lib/ajax/service.php?sesskey=<M.cfg.sesskey>&info=<method>`,
тело — `[{index:0, methodname, args}]`, ответ — массив, ошибка в `[0].exception.errorcode`.

`M.cfg.userId` — свой userid, отдельный запрос не нужен.

## Грабли СДО

**`limitnum` у календаря ограничен 50.** Больше — ошибка `Limit must be between 1 and 50 (inclusive)`,
причём не тихая: падает весь вызов.

**Брать `event.url`, а не `event.action.url`.** Второй ведёт на `&action=editsubmission` — это форма правки,
таблицы состояния там нет, разбор вернёт «?».

**`event.action.actionable` — не «сдано».** Это «можно действовать сейчас». У ещё не открытых заданий он тоже
ложный. Настоящий статус — только со страницы задания: строка `Состояние ответа на задание`,
значения `Отправлено для оценивания` / `Ответы на задание еще не представлены`. Есть готовое поле `event.overdue`.

Косвенный признак: сданное пропадает из `get_action_events_by_timesort`. Проверено на живом курсе.

## Пульс

API — gRPC-web, руками не дёргается. Только DOM.

Вход без пароля, если сессия СДО жива: переход на
`/api/auth/login?redirectUri=https%3A%2F%2Fpulse.mirea.ru%2Fservices&rememberMe=True`.
Ссылка «Войти» в шапке часто вне вьюпорта — не кликать по ref, а навигироваться прямо на этот URL.

| Раздел | URL |

## БРС

Два источника, они расходятся.

**Пульс `/services/merged-disciplines` — источник истины.** Карточка дисциплины это
`a[href^="/services/merged-disciplines/<uuid>/<uuid>"]`, внутри строками: форма (ЗАЧ/ЭКЗ), часть («1 / 3»),
название, `X из 120`, целевая оценка, `+N` за посещение, `ещё M` до порога.
Пороги и прогноз считает сам Пульс — брать готовые числа, своих не изобретать.

Шкала не у всех одна: физкультура шла `2 из 15`, а не из 120. Не хардкодить 120.

**СДО `/grade/report/user/index.php?id=<courseid>` — разбивка по элементам.**
Структура МИРЭА: Текущий контроль 0–40, Посещаемость 0–20, Достижения 0–10, Семестровый контроль 0–40,
Сумма баллов 0–120, плюс Оценка за промежуточную аттестацию.

Тип элемента приклеен к названию без пробела: `Вычисляемая оценкаТекущий контроль`,
`Заполняемый вручную элементПосещаемость`. Срезать префикс регуляркой.

**Расхождение между источниками — норма.** Проверено: по Информатике Пульс показывал 2.5 из 120,
а ведомость Moodle по тому же курсу была пустой целиком. Преподаватель может не вести ведомость в СДО.
При конфликте верить Пульсу и говорить об этом вслух.

Итог в `/grade/report/overview/index.php` (все курсы одним списком) почти всегда `-` — толку мало,
для БРС не использовать.

## Разметка журнала

Два swiper'а: `[0]` — недельный календарь (3 слайда), `[1]` — дни (~84 слайда).

- активная неделя: `.swiper-slide-active .weekly-calendar`
- выбрать дату: клик по `span` с числом внутри активного календаря
- пары выбранного дня: `.swiper[1] .swiper-slide-active a[href^="/lessons/visiting-logs/"]`
- листать недели: `.anticon-left` / `.anticon-right`

Карточку разбирать **по образцам, а не по номеру строки**: у прошедших и будущих пар порядок разный
(у прошедших нет строки «N пара»).

Месяц брать только из связки «месяц ГОД». Поиск просто по «ма» ловит «**Ма**тематический анализ» из карточек
и даёт май вместо сентября.

`\w` в JS не матчит кириллицу: `/\d+\s*недел\w*/` вернёт «4 недел». Писать `[а-яё]*`.

## Чётность недель (расписание, не журнал)

Журнал сам разрешает дату — ему чётность не нужна. Таблица `/services/my-schedule/...` — нужна:
у дней есть подвкладки «Нечетная/Четная», и `innerText` отдаёт обе сразу.

Фильтровать по числовому диапазону, а не по подписи: `2-16 н.` = недели 2..16, `кр. 1,18 н.` = все кроме
первой и восемнадцатой, `4,8,12,16 н.` = только перечисленные. Номер текущей недели — в заголовке.
